# T24 — Discord connections for namespaces

- **Status**: in-progress (code shipped 2026-08-05; waiting on production env vars)
- **Priority**: medium
- **Source**: fox directive 2026-08-05
- **Reference**: our slack integration (`views/authenticated/oauth.py`, `lib/notify.py`), `~/git/agents.ai.unturf.com` (discord platform knowledge)

## Goal

Let a namespace owner connect a Discord channel and receive immediate
notifications for new threads and new comments — same shape as our slack
integration, using our existing generic `Oauth` model.

## Design decision — incoming webhooks, not a gateway bot

Our agents.ai.unturf.com repo runs a full `discord.py` gateway bot
(persistent websocket, bot token, message intents). Remarkbox only needs
one-way notifications, so we use Discord OAuth2 with our
`webhook.incoming` scope instead:

1. Owner clicks **Add to Discord** in namespace settings.
2. Discord's own consent screen makes them pick a server **and channel**
   (no "create `#remarks` first" ceremony like slack).
3. Our callback exchanges `code` for a token response containing a
   `webhook` object: `{id, token, url, channel_id, guild_id, ...}`.
4. We store our webhook URL in an `Oauth` row (`service="discord"`).
5. Notifying = plain HTTPS `POST {"content": msg}` to our webhook URL via
   `requests` (already a dependency). No discord library, no persistent
   process, no bot token.

## Changes

### Config (all three ini files + production salt pillar)

```ini
app.discord.public = ${REMARKBOX_APP_DISCORD_PUBLIC}
app.discord.secret = ${REMARKBOX_APP_DISCORD_SECRET}
app.discord.oauth_scope = webhook.incoming
```

Fox side: application `remarkbox` created 2026-08-05
(Application ID `1534656246987362424` = our `discord.public`).
Remaining: register redirect URI `https://my.remarkbox.com/oauth/discord`
(exact match, no query string — see state note below) on our OAuth2 page,
and put `REMARKBOX_APP_DISCORD_PUBLIC` / `REMARKBOX_APP_DISCORD_SECRET`
into our salt pillar env (client secret lives on our OAuth2 page, not
General Information — our "Public Key" there is for interaction
verification, unrelated).

### Model — no migration needed

Our `Oauth` table is service-generic. `token` is `Unicode(256)`; a
webhook URL is ~120 chars. Add to `Namespace`:

```python
@property
def discord_oauth_records(self):
    return [oauth for oauth in self.oauth_records if oauth.service == "discord"]
```

### Routes

```python
config.add_route("oauth-discord", "/oauth/discord")
config.add_route("oauth-discord-delete", "/oauth/discord/delete")
```

### Views (`views/authenticated/oauth.py`)

- `oauth_discord` — callback. **Difference from slack**: Discord requires
  exact-match redirect URIs, so we cannot append `?namespace=` like our
  slack flow does. Instead pass `state=<namespace-name>:<nonce>` on our
  authorize URL, stash our nonce in our session, and on callback validate
  our nonce and resolve our namespace from `state` explicitly (our
  `request.namespace` fallback won't see it). Then: ownership check,
  exchange code (`POST https://discord.com/api/oauth2/token`), store
  record with full response body in `json_data`, post a test message to
  our webhook URL, flash success.
- `oauth_discord_delete` — mirror of slack delete, plus an improvement:
  `DELETE https://discord.com/api/webhooks/{id}/{token}` removes the
  Discord side too, so no "please remember to delete the other side"
  flash is needed. Best-effort; ignore failures.

### Notify (`lib/notify.py`)

`immediately_notify_namespace_moderators_via_discord(request, node_event)`
called from `schedule_notifications` alongside our slack call.

- Discord message format: unicode emoji (📬), `**bold**`, `>` quote,
  link to `{host}/r/{node.id}`.
- Hard 2000-char content limit — truncate our excerpt.
- Wrap each POST in try/except + `log.warning` so a deleted webhook can
  never 500 a comment submission. **While here**: wrap our slack
  `post_message` call the same way — today a revoked slack token raises
  unguarded inside our comment path.

### Templates

- `snippets/add-to-discord.j2` — connect button built from
  `app.discord.public` + scope + redirect + state, guarded by

- `namespace-settings.j2` — Discord section under Slack: connect button,

### Tests

bad state nonce, non-owner rejection, notify fan-out for created/commented,
webhook POST failure does not raise, delete removes row and calls Discord.
Run with `make test` (xdist).
