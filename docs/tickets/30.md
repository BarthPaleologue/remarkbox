# T30 — Comment import fails on shared author names and commits partial data

**Status:** resolved in this branch; pending upstream review
**Priority:** high
**Source:** reproduced during a customer migration from Cusdis, 2026-10-05

## Reproduction

Import an unrelated guest, another guest, a registered author named
`SharedAuthor` with an email, and a reply named `SharedAuthor` without an
email. Use the same import postfix for all four comments.

The registered author creates `SharedAuthor-backup` in `rb_user`. The guest
lookup queries `UserSurrogate` but filters `User.name`, producing a Cartesian
product. It matches unrelated surrogates and raises `MultipleResultsFound`.
With only one unrelated surrogate it can instead silently assign the wrong
author. Without a matching registered user it misses existing surrogates,
creating duplicate guest identities on subsequent imports.

The view catches the error and returns HTTP 200 with an error message.
Because no exception escapes the request, `pyramid_tm` commits the comments,
users and threads already flushed. The second pass restoring reply parents
does not run for the interrupted page. Retrying the file then creates
duplicate comments; the import does not deduplicate source comment IDs.

## Fix

- Filter `UserSurrogate.name` in the namespace-scoped, case-insensitive lookup.
- Doom the request transaction when import processing fails, so the error
  response cannot commit a partial import.
- Lock the import postfix only after successful processing; missing or invalid
  files must not permanently select a postfix.

No schema migration is needed. Existing partial imports and duplicate guest
identities are not changed automatically. Repeating a successful import still
creates additional comments; source-ID deduplication is outside this fix.

## Regression coverage

Tests use real SQLite sessions for guest lookup, namespace isolation,
case-insensitive matching, guest reuse, and a registered user whose name must
not match unrelated guests. A WebTest upload reproduces the shared-name
failure and verifies reply parents, timestamps, and separate identities.

A second upload fails on a later page after earlier writes were flushed.
It verifies that no nodes, users, surrogates, namespaces, URIs, or postfix lock
are committed, and that an existing comment remains unchanged.
