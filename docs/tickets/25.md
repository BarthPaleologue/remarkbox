## Problem

Our slack path runs on borrowed time and worse UX than our discord path:

- `slacker` is archived/unmaintained and drives Slack's **legacy v1**
  `oauth.access`. Slack stopped allowing new classic apps years ago —
  our flow keeps working only while our grandfathered app registration
  does, and it breaks on Slack's schedule, not ours.
- Owners must hand-create a `#remarks` channel (hardcoded target) and
  our connect test message posts to `#general` hoping it exists.
- Our old authorize URL passes `?namespace=` on the redirect URI (v2
  requires registered exact URIs) and carries no nonce — the discord
  flow got `state=<namespace>:<csrf>` protection in T24; slack never did.

## Goal

Slack OAuth **v2** with our `incoming-webhook` scope — structurally
identical to our discord flow: Slack's consent screen picks the
channel, `oauth.v2.access` returns `incoming_webhook.url`, delivery is
a plain HTTPS POST of `{"text": msg}`. No channel ceremony, no slack
library, one delivery mechanism for both services.

## Can we upgrade existing connected namespaces?

**No automatic conversion** — Slack only mints an incoming webhook URL
during the consent dance where a human picks the channel; a legacy
`xoxp-`/`xoxb-` token cannot be exchanged for one server-side.

**But legacy rows keep working**: their tokens still authorize
`chat.postMessage`, which needs only a plain `requests` POST with a
Bearer header — no slacker. So:

- Delivery becomes **dual-path**, keyed off the stored token: targets
  starting with `https://hooks.slack.com/` are v2 webhook rows (POST
  `{"text": ...}` to the URL); anything else is a legacy token (POST
  `chat.postMessage`, channel `#remarks`).
- Namespace settings mark legacy rows with a *reconnect to choose a
  channel* nudge; a reconnect adds a v2 row, then the owner deletes
  the legacy one.
- Nothing silently stops notifying. No migration, no data change —
  our generic Oauth table already fits both shapes in `token`.

## Changes

- `lib/slack.py` (new, mirrors `lib/discord.py`): `exchange_oauth_code`
  (v2, treats `ok: false` as failure), `post_webhook_message`
  (`{"text": ...}`, never raises), `post_chat_message` (legacy Bearer
  `chat.postMessage`, never raises), `revoke_token` (`auth.revoke`,
  best effort), `is_webhook_target`.
- `lib/notify.py`: slack delivery branches on `is_webhook_target`;
  `from slacker import Slacker` deleted.
- `views/authenticated/oauth.py`: `oauth_slack` rewritten on the
  discord pattern — `state=<namespace>:<nonce>` (session csrf), resolve
  namespace from state, ownership check, exchange via `lib.slack`,
  store `token=incoming_webhook.url` + full body in `json_data`,
  async success message to the granted webhook. `oauth_slack_delete`
  gains best-effort `auth.revoke` (v2 rows: `access_token` from
  json_data; legacy rows: the token itself) and drops the "remember to
  delete the Slack side" flash.
- `snippets/add-to-slack.j2`: v2 authorize URL + state; no more
  `?namespace=` on the redirect.
- `namespace-settings.j2`: "create #remarks first" copy removed;
  per-row rendering handles v2 shape (`team.name` +
  `incoming_webhook.channel`) and legacy shape (`team_name` +
  `#remarks` + reconnect nudge).
- ini (all three + pillar): `app.slack.oauth_scope = incoming-webhook`.
- requirements: `slacker` removed from requirements.txt,
  requirements.py3.txt, requirements-wsl.txt.
- `tests/test_slack.py` (new, mirrors test_discord.py): exchange
  ok/not-ok/error, webhook + legacy chat delivery, mixed-row fan-out,
  never-raise guards, oauth view success/denied/bad-state/non-owner,
  delete revokes.
