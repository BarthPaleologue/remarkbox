## Deploy sequence for namespace privacy

Migrations are not automated in this project. Before enabling list privacy on
any deployment:

1. `make migrate` — applies `554e2329ebf0`, backfilling every namespace to
   `public = True` so current behaviour is preserved.
2. Confirm: no namespace should read `public = 0`.
3. Set `namespace.enforce_private_lists = true` in that deployment's ini.

The flag defaults to false, so deploying the code alone changes nothing.

**Correction (2026-07-27):** an earlier note here claimed no migration step
existed. That was wrong — it searched `remarkbox-states`, which is stale
jenkins-era, and our CI config. Salt is what deploys us, and
`foxhop-states/uwsgi/sites.sls:315` runs
`alembic upgrade head` on every release, `onchanges` the new tarball moving
into place. Production therefore applied `554e2329ebf0` and `df0217588814`
when `5acecdd` deployed, which matches production answering 401 rather than
500 for a bearer request.

Steps 1 and 2 above are consequently already done for our hosted deployments;
they remain the sequence for a self-hoster or a restored database.
