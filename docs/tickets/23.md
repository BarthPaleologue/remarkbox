# T23 — Deployed virtualenv is missing pkg_resources

**Status:** fix pushed — verify on origin after deploy
**Priority:** medium
**Source:** noticed 2026-07-28 while diagnosing [T22](22.md)

## Symptom

On origin, inside our deployed virtualenv:

```
$ env/bin/python -c "from pyramid.paster import get_appsettings; ..."
ModuleNotFoundError: No module named 'pkg_resources'
```

`pyramid.asset` does `import pkg_resources`, which setuptools removed in 81.

## Why this is odd

Our CI pins it — `.unforge/workflows/ci.yml` runs
`env/bin/pip install 'setuptools<81'` in both our test and build jobs — and
`CLAUDE.md` records the same requirement from our 2026-03-30 CWE-407 audit. So
either that pin is not surviving into our shipped tarball, or something later
in our deploy upgrades setuptools.

Alembic still runs (that is how T22 was diagnosed), and our app serves traffic
normally, so this is not currently breaking production. It breaks any tooling
that goes through `pyramid.paster` — which includes `pshell`, and our own
`scripts/` that call `get_appsettings`.

## Root cause — confirmed

`requirements.py3.txt` listed `setuptools` unpinned, so
`requirements-prod.lock` resolved it to **82.0.1**. Our Makefile does install
`setuptools<81` first, but `install-source-prod` then runs

```
pip install --require-hashes -r requirements-prod.lock
```

which upgrades straight over that pin. Origin confirmed it:

```
Name: setuptools
Version: 82.0.1
ModuleNotFoundError: No module named 'pkg_resources'
```

The pin was in the place that builds the venv, not the place the lock is
generated from — so it never survived.

## Fix

`requirements.py3.txt` now says `setuptools<81`, and the lock was regenerated
to match: `setuptools==80.10.2`.

Regenerated **without** `--upgrade`. `make pins-lock` passes `--upgrade`, which
moved sqlalchemy, pyramid, stripe, zope-interface and a dozen others in one
go — a broad dependency bump has no business riding along with a one-line
pin, least of all days after an outage. The shipped diff is three lines.

## Remaining

- Confirm `env/bin/python -c "import pkg_resources"` succeeds on origin once
  the deploy lands.
- Lift the cap when pyramid stops importing `pkg_resources`. Pinning
  setuptools forever is a slow leak: we are holding back a build tool to keep
  a deprecated API alive. Check whether a newer pyramid has migrated.
