# T23 — Deployed virtualenv is missing pkg_resources

**Status:** open
**Priority:** medium
**Source:** noticed 2026-07-28 while diagnosing [T22](22.md)

## Symptom

On origin, inside our deployed virtualenv:

```
$ env/bin/python -c "from pyramid.paster import get_appsettings; ..."
ModuleNotFoundError: No module named 'pkg_resources'
```

`pyramid.asset` does `import pkg_resources`, which setuptools removed in 81.

## Why this is odd

Our CI pins it — `.unforge/workflows/ci.yml` runs
`env/bin/pip install 'setuptools<81'` in both our test and build jobs — and
`CLAUDE.md` records the same requirement from our 2026-03-30 CWE-407 audit. So
either that pin is not surviving into our shipped tarball, or something later
in our deploy upgrades setuptools.

Alembic still runs (that is how T22 was diagnosed), and our app serves traffic
normally, so this is not currently breaking production. It breaks any tooling
that goes through `pyramid.paster` — which includes `pshell`, and our own
`scripts/` that call `get_appsettings`.

## Investigate

```bash
cd /opt/remarkbox && env/bin/pip show setuptools | head -2
```

Compare with what CI pinned. If our tarball ships a newer setuptools, find out
where it comes from — `virtualenv-clone`, or a dependency pulling it forward.

## Fix

Restore the `setuptools<81` pin so it survives into our deployed environment.
Longer term, pyramid needs to stop importing `pkg_resources`; check whether a
newer pyramid has done so, since pinning setuptools forever is a slow leak.
