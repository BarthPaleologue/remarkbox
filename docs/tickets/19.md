# T19 — Test suite instability: cross-module state coupling

- **Status**: resolved
- **Priority**: high
- **Source**: fox directive 2026-07-27 ("solve the root issue"); blocker noted during T18 review
- **Resolved**: 2026-07-27

## Problem

Our suite was nondeterministically red: 13–116 failures across identical
trees, worse whenever a new test module (e.g. `test_security.py`) joined the
collection. Serial runs showed ~129–151 phantom failures. This blocked any
trustworthy regression net ahead of undigg.com signups (T17).

## Root causes (three, all shared-mutable-state — MOAD-0002 shaped)

1. **One database per worker, many modules per worker.** Every test module
   builds its own app from `test.ini`, all binding the same per-worker SQLite
   file. Six modules call `Base.metadata.drop_all()` in `tearDownClass`.
   Under `--dist=loadgroup` with no group marks, xdist deals tests out
   individually, interleaving classes from different modules on one worker —
   each drop yanked tables from whichever sibling was mid-flight. Adding any
   module reshuffled scheduling, which is why failure counts moved.

2. **Process-global `transaction.manager`.** All modules join sessions to the
   one thread-local manager and nobody ends transactions at module
   boundaries. A commit in module B two-phase-voted over module A's dead
   session: `ResourceClosedError`, then a cascade poisoning every later test.
   This alone explains the historical "serial pytest fakes 151 failures".

3. **Nested conftest invisible to the xdist master.** Database cleanup hooks
   lived in `remarkbox/tests/conftest.py`; without explicit path arguments
   the master process never loads a nested conftest, so cleanup silently
   never ran on full runs. Interrupted runs left stale databases whose rows
   masqueraded as failures (`test_push` `already_subscribed`).

## Fix

- `conftest.py` moved to repo root (loads in master and workers):
  - `pytest_runtest_setup` points `TEST_DATABASE_PATH` at a per-worker,
    **per-module** database file and calls `transaction.abort()` before every
    test.
  - `pytest_configure` (master) purges stale `test-remarkbox_*.sqlite*` at
    session start; `pytest_unconfigure` purges at end.
- Every test module carries `pytestmark = pytest.mark.xdist_group("<module>")`
  so its tests travel as one unit (`test_pandoc.py` keeps its existing
  class-level `pandoc-subprocess` group).
- Dead `db_engine` fixture removed with the old nested conftest.

## Verification

- Parallel `-n auto --dist=loadgroup`: 604 passed, five consecutive green
  runs, including runs started from a deliberately poisoned state; zero
  leftover databases; wall time down from ~130–240s to ~80–90s.
- Serial `-p no:xdist`: 604 passed (previously ~129–151 failures).
