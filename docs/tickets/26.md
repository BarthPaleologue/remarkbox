# T26 — LLM relevance pipeline: silent drift, blind model pick, hostage CI

**Status:** resolved
**Priority:** high
**Source:** fallout from the 2026-08-30 deploy block; fox directive 2026-08-31

## What happened

A push on 2026-08-30 could not deploy. Our pipeline went red at `test`, so
`build` was skipped and our `deploy` child never triggered. Our fix waiting
behind it ([288101d](../..), owner access to moderator views) sat undeployed.

Nothing in that push touched our LLM code. `main` had been green through
2026-08-07, then sat idle 24 days. During that gap our inference endpoint
stopped serving `solidrust/Hermes-3-Llama-3.1-8B-AWQ`. Our first push after
the gap inherited a suite our own code had not broken.

## Three defects, one root

### 1. Blind model selection

`_discover_model` took `data["data"][0]["id"]` — whatever our server happened
to list first silently became our classifier. Our endpoint had swapped to
`Lorbus/Qwen3.6-27B-int4-AutoRound`, a reasoning model. Worse, discovery only
ran as a 404 *fallback*, so our stale configured id was tried first every time.

### 2. Silent degradation

Reasoning models open with a thinking monologue. `_parse_verdict` reads our
first line only, so every verdict came back `None`.

`None` is not treated as an error anywhere:

- `api/views.py:133` acts on `if relevant is False:`, so an unreadable verdict
  adds no spam signal. Our relevance check went **inert, not wrong**.
- `lib/theme_palette.py` shares our call path and is deliberately strict, so it
  rejected every model palette and fell back to hash palettes.

Both features degraded to a safe default and said nothing. Two features were
dead for weeks with zero signal.

### 3. CI hostage to a third party

Twelve integration tests hit `hermes.ai.unturf.com` on every run. Their
`setUpClass` skipped when our endpoint was *unreachable*, but our endpoint was
perfectly reachable — it just answered differently. So they failed, and a
third party's model swap blocked our deploys.

## What we changed

**Model detection is deliberate** (`models/spam_llm.py`)

`_llm_request` now resolves our model from `/v1/models` *before* our first
request. New `_choose_model` prefers our configured id when upstream actually
serves it, falls back to our only id on offer, and when several are served
with none configured, sorts for reproducibility and logs a warning. A
mid-process 404 drops our cached id, rediscovers once and retries.

**Reasoning is suppressed per request**

Probed against our live vLLM endpoint rather than guessed:

| key | effect |
|-----|--------|
| *(baseline)* | `"Here's a thinking process:"` |
| `chat_template_kwargs.enable_thinking` | **verdict on first line** |
| `reasoning_effort: "none"` | **verdict on first line** |
| `enable_thinking` (top level) | accepted, ignored |
| `thinking.type` | accepted, ignored |

vLLM accepts unknown fields without erroring, so the two dead keys would have
looked harmless while doing nothing. Only our two that work are sent.

**Degradation is now audible**

`_parse_verdict` logs a warning when a verdict is unreadable, naming our first
line. New `health_check()` classifies a known-relevant canary and reports
`ok`/`model`/`verdict`/`detail`. `scripts/check_llm_health.py` wraps it and
exits non-zero when degraded, so cron or a monitor can see it.

```bash
make check-llm
python scripts/check_llm_health.py --endpoint https://host/v1/chat/completions --json
```

**CI cut loose from live endpoints**

Live tests carry an `integration` marker via a shared `LiveEndpointTestCase`,
which also removes our reachability probe that was copy-pasted into four
classes.

| target | runs |
|--------|------|
| `make test` | unit only (`-m "not integration"`) — our CI path |
| `make test-integration` | live endpoints only |
| `make test-all` | everything |

Verified under a simulated blackout (`https_proxy` to a dead port): our CI path
passes, and our integration path **skips** rather than fails.

## Why one chokepoint matters

`lib/theme_palette.py` imports `_llm_request` from `spam_llm`, so both
consumers inherit every fix with no second edit. A sweep confirmed no path
bypasses `_post_chat`; other outbound calls (Slack, Discord, webmention,
namespace_request) are not inference.

## Notes for next time

- Both failure modes degraded to safe defaults. That is correct at runtime and
  invisible to operators. Any future fail-soft path needs a matching health
  check, or it will rot unnoticed the same way.
- Our 24-day idle gap hid this. Nothing pushed, so nothing reported. A periodic
  `make check-llm` would have caught it on day one.
- Our deployed version endpoint is our ground truth, not a green parent
  pipeline. `deploy` is a triggered child; a green parent only means it handed
  off.
